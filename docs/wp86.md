# wp86:伺服器營運面(`server.properties`、伺服器列表、RCON、Query、聊天、閒置暫停、日誌)

分支 `wp86-server-ops`(從 main `b367b801` 開出,只推到 `vm`)。目標:真的把 Kiln 當伺服器跑的人,在遊戲開始之前碰到的東西——設定檔、伺服器列表、遠端管理、聊天——都和 vanilla 26.3 的 dedicated server 一樣。做法承襲 wp72~wp85:**`javap` 讀 vanilla 位元碼**(`net.minecraft.server.dedicated.*`、`server.rcon.*`、`ServerStatus`、`ServerGamePacketListenerImpl`、`network.chat.*`、`MinecraftServer.tickServer`、`Main`、`Eula`),再**用同一份 `server.properties`、同一個種子啟動 vanilla 和 Kiln 並排比**。讀位元碼的小工具在 `tools/wp86/jtools/`(`javap` 輸出壓成一行一個指令)。

## 1. 怎麼把 Kiln 當伺服器跑

```sh
cd /srv/kiln                        # 工作目錄:所有檔案都在這裡讀寫(跟 vanilla 一樣)
cp /path/to/server.jar .            # 你自己的 vanilla 26.3 server.jar(Kiln 不附 Mojang 資料,見下)
kiln --initSettings                 # 寫出 server.properties 與 eula.txt 就結束(和 vanilla 的 --initSettings 一樣)
$EDITOR eula.txt                    # eula=true
kiln --nogui                        # 啟動;Ctrl-C 或主控台打 stop 結束
```

命令列和 vanilla 的 `Main` 一樣:`--nogui`(收下)、`--initSettings`、`--port <n>`、`--world <名稱>`、`--universe <目錄>`、`--pidFile <檔>`、`--serverId`、`--help`,以及只對 Java 版有意義的 `--demo --bonusChest --forceUpgrade --eraseCache --recreateRegionFiles --safeMode --jfrProfile`(收下、不做事)。不認得的選項會印一行錯誤並以狀態 1 結束。

### 讀與寫的檔案(相對於工作目錄)

| 檔案 | 讀/寫 | 說明 |
|---|---|---|
| `server.properties` | 讀,**每次啟動寫回** | 缺的鍵補 vanilla 的預設值,壞值換成預設值/夾到範圍,依鍵排序,第一行 `#Minecraft server properties`、第二行日期(`Properties.store` 的格式);**不認得的鍵原樣保留**。不存在時照 vanilla 全部建出來(含隨機的 `management-server-secret`) |
| `eula.txt` | 讀,缺時寫 | 缺檔:寫出 `eula=false` 的預設檔並結束(`You need to agree to the EULA in order to run the server. Go to eula.txt for more info.`);不是 `eula=true`(不分大小寫)也結束 |
| `server-icon.png` | 讀 | 伺服器列表的圖示,**必須是 64×64 的 PNG**,否則記 `Couldn't load server icon` 並不送(同 vanilla)。沒有時找世界目錄的 `icon.png` |
| `whitelist.json`、`banned-players.json`、`banned-ips.json`、`ops.json` | 讀寫 | 同 vanilla(wp8x 已有) |
| `<level-name>/`(或 `--universe`/`--world` 指的) | 讀寫 | 世界。`level-name` 預設 `world`;沒有存檔就建新世界(`level-seed`、`gamemode`、`hardcore`、`generate-structures`、`difficulty` 用在新世界) |
| `codeofconduct/<語言>.txt` | 讀 | `enable-code-of-conduct=true` 時 |
| `logs/latest.log`、`logs/<日期>-<n>.log.gz` | 寫 | 見 §7 |
| `crash-reports/crash-<日期>-server.txt` | 寫 | `max-tick-time` 看門狗觸發時 |
| `server.jar` 或 `versions/*/server-*.jar`(或 `KILN_JAR`) | 讀 | **只讀裡面的 `assets/minecraft/lang/en_us.json`**,讓主控台、RCON 和 Query 印 vanilla 的英文句子(`There are 0 of a max of 20 players online:`);找不到就印翻譯鍵(`commands.list.players[0, 20, ]`)並警告。Kiln 本身不含也不提交任何 Mojang 資料 |
| `generated/`(或 `KILN_DATAPACK`、`work/generated`) | 讀 | vanilla 的 worldgen 資料(資料產生器的輸出),`level-type=minecraft:normal` 的地形要用;找不到時警告並生成超平坦世界 |

### `KILN_*` 環境變數

變數**永遠壓過** `server.properties`(例:`KILN_PORT=25570` 蓋過 `server-port`)。Kiln 自己的設定(`KILN_TICK_THREADS`、`KILN_PLUGINS_DIR`、`KILN_REGIONS`、`KILN_GEN_THREADS`、`KILN_ENABLE_COMMAND_BLOCK`…,vanilla 沒有對應鍵的)照舊,見 `main.rs` 與各模組的說明。測試用的 harness 不需要改:**只要設了 `KILN_WORLD`、`KILN_PORT` 或 `KILN_GENERATOR` 而且沒有 `server.properties`**,Kiln 照 wp86 之前的方式跑(離線模式、不開白名單、100 人、不建 `server.properties`/`eula.txt`、不問 EULA、日誌用舊格式)。

## 2. `server.properties` 逐鍵(vanilla 26.3 共 63 個鍵)

預設值與解析規則取自 `DedicatedServerProperties`/`Settings`(`javap`):布林用 `Boolean.valueOf`(只有 `true` 是真,任何大小寫),整數用 `Integer.parseInt`(**含空白、小數、`+`以外的怪字都不是數字 → 換成預設值**;`+12` 是 12),`difficulty`/`gamemode` 數字當 id(難度 id 取模 4、模式越界為生存)、文字當名稱(認不得的難度是 easy、模式是 survival),`level-type` 轉小寫,`max-world-size` 夾 1~29,999,984,`entity-broadcast-range-percentage` 夾 10~1000 但**不是數字會直接丟例外**(vanilla 啟動失敗;Kiln 同樣以錯誤結束),`op-permission-level`/`function-permission-level` 夾 0~4,`resource-pack-hash` 讀後從檔案移除(舊鍵),`announce-player-achievements` 讀後移除並設 `show_advancement_messages`。`properties::tests`、`javaprops::tests` 有這些規則的單元測試。

| `motd`、`max-players`、`hide-online-players`、`enable-status` | 伺服器列表、Query、舊版 ping、登入人數上限(§3) |

## 3. 伺服器列表

`MinecraftServer.buildServerStatus`:JSON 欄位依 `ServerStatus.CODEC` 的順序、預設值的欄位不寫(空描述、空 sample、`enforcesSecureChat:false`),字串用 Gson 的跳脫(不跳脫 `<` `&` `'`,但 U+2028/2029 寫成 ` `)。`players.sample` 是 `buildPlayerStatus`:最多 12 位**連續**玩家(從隨機起點)、關閉「在伺服器列表顯示」的玩家換成 `Anonymous Player`(全零 UUID)、順序洗牌;`hide-online-players=true` 沒有 sample。`favicon` 是 `data:image/png;base64,…`。每個連線一次 status 請求(第二次斷線);`enable-status=false` 時連 status 與舊版 ping 都不回(直接關)。舊版 ping(`FE`、`FE 01`、1.6 的 `FE 01 FA MC|PingHost`)回 kick 封包 `§1\0127\0<版本>\0<motd>\0<人數>\0<上限>`(`LegacyQueryHandler`)。登入拒絕用可翻譯文字:`multiplayer.disconnect.incompatible`/`outdated_client`(協定 < 754)帶版本名、`multiplayer.disconnect.server_full`。每 5 秒重建一次(`STATUS_EXPIRE_TIME_NANOS`)。

測試:`kiln-net/src/status.rs` 的 4 個單元測試、`tests.rs` 的 `the_status_names_the_players_and_the_icon`、`hide_online_players_…`、`the_legacy_pings_…`、`login_refusals_…`。

## 4. RCON 與 Query

`crates/kiln-server/src/rcon.rs`(`RconThread`/`RconClient`):封包 `長度、請求 id、型別(小端 int)、本文、兩個 NUL`;一次最多讀 1460 位元組當一個封包,長度不符/不足 10 位元組就關連線;型別 3 登入:密碼非空且相同 → 回 `(id, 2, "")`,否則 `(-1, 2, "")`(並登出);型別 2 指令:未登入回 `(-1, 2, "")`,已登入以 **RCON 來源**(權限 4、出生點、名稱 `Rcon`、`acceptsSuccess/Failure`、`shouldInformAdmins` = `broadcast-rcon-to-ops`)在模擬的下一個 tick 的 G 階段執行,回應切成每片 4096 字元(至少一片,空回應也有一個空封包);其他型別回 `Unknown request <hex>`。指令輸出就是 `Component.getString()` 接起來(沒有換行)。埠 0~65535 之外、密碼空白時停用並記 `Invalid rcon port … rcon disabled!`/`No rcon password set in server.properties, rcon disabled!`。

`query.rs`(`QueryThreadGs4`):UDP,`FE FD`;型別 9 握手回 `\t<session 4 位元組>\<挑戰碼十進位>\0`(挑戰碼 `nextInt(1<<24)`,依來源位址記 30 秒);型別 0 帶挑戰碼:15 位元組長的請求是完整 stat(`splitnum\0\x80\0hostname…player_\0\0<名字>\0…`,5 秒快取,快取中換 session id),其餘是基本 stat(`motd\0SMP\0<世界名>\0人數\0上限\0<埠 short 小端><hostip>\0`)。`hostip` = `server-ip`,空白時取本機位址。

測試:`rcon/tests.rs` 6 個、`query/tests.rs` 7 個(逐位元組比對 stat 回應、錯的挑戰碼不回、快取)、`server_ops.rs` 的 `an_rcon_command_runs_at_level_four…`。

## 5. 聊天

玩家說話 → 廣播 `PLAYER_CHAT`(`ClientboundPlayerChatPacket`:全域序號、發送者、鏈序號、簽章、內容、時間、salt、「已見訊息」清單、未簽章內容、過濾遮罩、聊天型別 + 名稱),取代舊版把玩家說話當 `DISGUISED_CHAT` 送的做法。名稱元件帶 `click_event`(`suggest_command /tell 名字 `)、`insertion`、`hover_event`(`show_entity`)——`CompoundTag` 的欄位順序也跟 Java 的 `HashMap` 順序一樣(`Tag::java_ordered`),所以位元組相同。

* **離線模式或沒有聊天 session**:訊息不簽章(`signed=false`、鏈序號 0),客戶端顯示「不安全」;日誌行前綴 `[Not Secure]`。`enforce-secure-profile` 且 `online-mode`:沒有 session 的玩家說話被拒,只收到紅字 `chat.disabled.missingProfileKey`。
* **聊天 session**(`ServerboundChatSessionUpdatePacket`):金鑰要是 Mojang 的 services 金鑰(線上模式啟動時背景向 `getPublicKeys` 取,失敗重試 5 次)用 `SHA1withRSA` 簽過 `玩家 UUID ‖ 到期毫秒 ‖ 金鑰 DER`;通過後廣播 `INITIALIZE_CHAT`,新登入的玩家在 `Player Info` 裡就帶別人的 session。沒有 services 金鑰時記 `Ignoring chat session from … due to missing Services public key` 並忽略(vanilla 同)。更早到期的金鑰 → `multiplayer.disconnect.expired_public_key`;簽章不對 → `invalid_public_key_signature`;金鑰不是 RSA → 封包解碼失敗。
* **訊息鏈**(`SignedMessageChain`):每則簽章訊息 `SHA256withRSA` 驗 `1 ‖ 發送者 ‖ session ‖ 序號 ‖ salt ‖ 秒 ‖ 內容 ‖ 已見簽章`;時間倒退 → `chat.disabled.out_of_order_chat`;簽章錯 → `invalid_signature`;鏈斷了之後 → `chain_broken`;金鑰過期 → `expiredProfileKey`;都是**只告訴玩家(紅字),不斷線**,日誌記 `Failed to update secure chat state`。
* **已見訊息**(`LastSeenMessagesValidator`,視窗 20)與簽章快取(`MessageSignatureCache`,128 槽):發出去的簽章訊息進「待確認」;客戶端的 `offset`/確認位元/校驗碼不合 → `multiplayer.disconnect.chat_validation_failed`;待確認超過 4096 → `too_many_pending_chats`;接收者的「已見」清單用快取槽號(`id+1`),沒有才送完整簽章。
* **指令**:`chat_command` 與 `chat_command_signed`(有可簽章參數的 `/say`、`/msg`、`/me`、`/teammsg` 客戶端一律用後者)。簽章參數成為 `PlayerChatMessage`,所以 `/say` 送出去是 `PLAYER_CHAT`(聊天型別 `say_command`),`/msg` 對收件人與自己各一則;在 `enforce-secure-profile` 下送無簽章的 `chat_command` 但指令有可簽章參數 → `chat.disabled.invalid_command_signature`。主控台/RCON/指令方塊說的話是「系統訊息」,仍用 `DISGUISED_CHAT`。
* **斷線與提示**(都與 vanilla 並排比過):含 `§` 或控制字元 → `multiplayer.disconnect.illegal_characters`;聊天選項「隱藏」→ 紅字 `chat.disabled.options`、「只有指令」/隱藏的玩家收不到聊天(`SYSTEM_CHAT` 的動作列仍收);太快 → `disconnect.spam`(OP 除外,每則 +20、門檻 `20×秒數`、每 tick −1);長度 > 256 或封包讀不完 → 客戶端收到 `disconnect.genericReason`:`Internal Exception: io.netty.handler.codec.DecoderException: Failed to decode packet 'serverbound/minecraft:chat'`。
* `PlayerInfo` 的玩家名稱、`Tag` 的聊天事件、`ClientInfo` 的 `chat_visibility`、`allows_listing` 也補上了。

## 6. 閒置暫停、閒置踢人、看門狗

* **`pause-when-empty-seconds`**(`MinecraftServer.tickServer`):沒有玩家(且不是 `/tick sprint`)連續 `秒×20` tick 後,記 `Server empty for N seconds, pausing`、存檔一次,之後**整個世界不 tick**:時間、天氣、作物、紅石、生物、區域都停;只有連線層仍轉(主控台指令、RCON、查詢回覆、玩家登入)。有玩家登入的那個 tick 就恢復。預設 60;0 以下關閉。
* **`player-idle-timeout`**:分鐘;沒動作(移動、聊天、指令…不含保活/區塊確認)就踢 `multiplayer.disconnect.idling`。
* **`max-tick-time`**(`ServerWatchdog`):模擬每 tick 公布下一個 tick 應該開始的時間;看門狗執行緒發現晚了超過 `max-tick-time` 毫秒就記 `A single server tick took 60.00 seconds (should be max 0.05)`、`Considering it to be crashed, server will forcibly shutdown.`,寫 `crash-reports/crash-<日期>-server.txt`(`---- Minecraft Crash Report ----` / `Description: Watching Server` / `-- Head --` / `-- Performance stats --` / `-- System Details --`,內容比 vanilla 少:沒有 Java 執行緒傾印)並以狀態 1 結束。0 以下關閉。

## 7. 日誌

有 `server.properties` 的伺服器用 vanilla 的格式 `[HH:MM:SS] [Server thread/INFO]: 訊息`(時間是機器時區;模擬執行緒叫 `Server thread`、其他執行緒用自己的名字)印到標準輸出,同時寫 `logs/latest.log`;啟動時把上一份 `latest.log` 壓成 `logs/<今天日期>-<n>.log.gz`(n 從 1 起第一個空的),空檔不壓。額外的幾行 vanilla 也有:`Starting minecraft server version 26.3`、`Loading properties`、`Default game type: SURVIVAL`、`Starting Minecraft server on *:25565`、`Done (X.XXXs)! For help, type "help"`、`Starting GS4 status listener`、`Starting remote control listener`、`Thread RCON Listener started`、`RCON running on …`。控制台對系統訊息(指令回覆、`/stop` 的 `Stopping the server`、`X joined the game`/`X left the game`)和 vanilla 26.3 一樣在前面加 `System chat: `(`MinecraftServer.sendSystemMessage`;並排用 `list`、`seed`、`whitelist list`、`say` 對 vanilla 量到),聊天則是 `[Not Secure] <名字> 訊息`。harness 模式(沒有 `server.properties`)維持舊的純文字行。`RUST_LOG` 照舊(預設 `info`)。

## 8. 管理伺服器(`management-server-*`)

完整說明在 `docs/wp86-mgmt.md`(分支 `wp86-mgmt`,由另一個 Claude 工作階段做,已併入本分支)。摘要:

* `management-server-enabled`(預設 `false`)開啟後,Kiln 在**載入世界之前**開一個 JSON-RPC 2.0 over WebSocket 的伺服器(`management-server-host`/`-port`/`-secret`/`-tls-enabled`/`-tls-keystore`/`-tls-keystore-password`/`-allowed-origins`、`status-heartbeat-interval`;鍵與驗證和 vanilla 的 `DedicatedServerProperties` 相同,密鑰缺少時產生 40 個英數字寫回檔案)。連線帶 `Authorization: Bearer <密鑰>` 或(瀏覽器)`Sec-WebSocket-Protocol: minecraft-v1, <密鑰>` 加 Origin。
* 68 個方法(允許名單、封鎖、IP 封鎖、玩家與踢人、管理員、`server/*`、20 個 `serversettings/*`、遊戲規則)與 21 個通知(`server/started|stopping|saving|saved|activity|status`、`players/joined|left`、名單的 added/removed、`gamerules/updated`),`rpc.discover` 回 OpenRPC 文件;指令(`/whitelist`、`/op`、`/ban`、`/gamerule`、`/save-all`、`/stop`)與玩家進出也會觸發通知。
* 跟 vanilla 並排(同一份腳本打兩邊、比原始文字):基本/名單/伺服器/邊界/玩家/壞 JSON 解析/TLS/握手(57 種)/啟動中請求,共六百多個請求一致;已知差異列在 `docs/wp86-mgmt.md` 末尾(遊戲規則列出順序、`view_distance` 不重送給在線客戶端、離線模式不向 Mojang 查名字、Hixie 草案握手只回 101、`world/upgrade_*` 從不送)。
* 順手改進:模擬迴圈在等下一個 tick 的空檔就處理管理與 RCON 的工作(以前要等到下一個 tick 開頭,一個請求 50 ms;現在約 40 µs)。

## 10. 沒做 / 與 vanilla 不同

* **簽章聊天沒有用真的 Mojang 帳號試過**(沒有帳號可用):金鑰驗證與訊息鏈用自己產生的 RSA 金鑰對照 vanilla 位元組格式測(`signed_chat.rs` 4 個),線上模式取 Mojang 金鑰的 HTTP 路徑只有文件解析的單元測試。
* `generator-settings`、`region-file-compression`、`sync-chunk-writes`、`text-filtering-*` 讀了不用;`level-type` 只認 `normal`/`flat`。
* 看門狗的當機報告沒有 Java 執行緒傾印。
* 浮空檢查多約 1 秒(載入等待)。
* 聊天過濾(`FilteredText`)沒有,遮罩恆為 pass-through。
* 登入的日誌行(`Alice[/127.0.0.1:33820] logged in with entity id …`、`Alice lost connection: …`)Kiln 是自己的格式(`Alice (uuid) joined from …`、`Alice (addr) left: …`);其他不在上面列出的日誌行不逐行對。
* 看似重複的 `Server thread` 以外的執行緒名稱(`ServerMain` 在主執行緒)與 Log4j 的 `Netty Server IO #n` 不同。

## 11. 驗證怎麼跑

    nohup ~/kt wp86-server-ops bash tools/wp86/verify86.sh > ~/wp86/v/all.out 2>&1 &    # 每一步一個輸出檔 ~/wp86/v/<步驟>.out
    # 步驟:check test_data test_nodata test_default build parity cmpdiff1 cmpdiff2 cmpdiff3 plugins neg(也可以只列要的步驟)
    bash ~/wp86/final_cmp.sh          # 聊天/聊天錯誤/RCON/Query 與 vanilla 並排(tools/wp86/final_cmp.sh)
    bash tools/wp86/neg86.sh [名稱]   # 負向檢查:每項把一個修正改回去,守它的測試必須失敗
