# Vanilla gameplay parity cost, extensibility options, and ops/security for a Rust Minecraft Java server (as of 2026-09)

## Context (time-sensitive)
- Latest Java release is **26.3** (Sep 15 2026, protocol **777**, data version 5023). 26.4 snapshots have started. Mojang now ships quarterly: 26.1 (Mar 24, proto 775), 26.2 (Jun 16, 776), 26.3 (Sep 15, 777). Each drop changes the protocol and the worldgen/data formats. 26.1 was also the first release shipped only unobfuscated, needs Java 25, and restructured the world save layout (per-dimension folders, `players/`).
- Unobfuscated vanilla source can be decompiled with GitCraft. SteelMC does this in `update-minecraft-src.sh`. That makes line-by-line porting and differential testing much cheaper than in the obfuscated era.

## Part A: parity cost
**What is data-driven vs hand-ported.** The vanilla data generator (`java -DbundlerMainClass=net.minecraft.data.Main -jar server.jar`) plus datapack JSON gives you parameters: block states and IDs, registries, packets, the command tree, worldgen JSON (noise settings, density functions, surface rules, configured/placed features, structures, template pools, NBT structure templates), loot tables, recipes, advancements and tags. The algorithms that interpret those parameters still have to be ported by hand: density-function semantics, aquifers, ore veins, about 60 feature types (with tree trunk/foliage placers), legacy piece structures (fortress, mansion, stronghold, monument, end city, mineshaft), the jigsaw assembler, the lighting BFS, scheduled ticks and block updates, every block behaviour, entity physics and AI, loot functions and conditions, advancement triggers, and around 80 commands.

Pumpkin and SteelMC both do build-time codegen from extracted JSON. Pumpkin's `tools/pumpkin-codegen` turns JSON into Rust statics. SteelMC's `steel-worldgen/build/density/transpiler` compiles density-function trees into native Rust with common-subexpression elimination, bounds-based branch elision and SIMD. The worldgen DSL keeps changing, though. 26.3 snapshots added about 14 density-function types and removed `cache_2d`, `flat_cache`, `cache_all_in_cell` and `shifted_noise`. 26.2 added `interval_select` and new feature and surface-rule types. So a codegen pipeline has to be re-run and re-validated every quarter. Custom datapack worldgen also needs a runtime interpreter as a fallback.

**Worldgen parity is achievable but subtle.** SteelMC (created Oct 2025) reached block-for-block parity on May 20 2026. Its suite tests 7,500 random chunks, 2,500 per dimension, against a vanilla reference with entity spawning excluded. The catch is that vanilla worldgen is not deterministic under multithreading. Steel had to patch its vanilla extractor (per-chunk biome cache reset, fixed feature order across chunk borders, explicit ordering of hash collections) to get a reproducible reference. Steel's benchmark: a 10,201-chunk overworld in a median 3.95 s on a Ryzen 9 9950X, 18.8x faster than Fabric, or 2.75x per CPU-second.

Pumpkin's tests compare against vanilla chunk dumps taken with blending and structure beardifier off. They allow **up to 6,000 mismatched blocks per chunk**, so they are not a bit-exact gate. Pumpkin also embeds vanilla's constructed multi-noise RTree (`multi_noise_biome_tree.json`) instead of rebuilding it, and uses fingerprint hashes to catch regressions.

Parity-critical details: Java LCG and Xoroshiro128++ RNG, MD5-seeded positional random, Mth lookup tables, and float operation order. Whether the new `log`/`pow` density functions are bit-stable across JVMs is unverified.

Alternatives to porting worldgen: flat or void worlds; a custom Rust generator; or pre-generate with vanilla/Paper plus Chunky and import Anvil. Anvil uses 4 KiB sectors, zlib, and optionally LZ4 (compression type 4, since 24w04a), with `.mcc` files for chunks over 1020 KiB. Only accept worlds at the current DataVersion (upgrade with vanilla `--forceUpgrade`) to avoid porting DataFixerUpper.

**Lighting.** Vanilla rewrote its light engine in 1.20 (23w17a), largely absorbing Starlight's ideas. Starlight's repo is archived (Mar 2024). Starlight's technique: BFS queues that propagate from one source direction, with separate increase and decrease queues. It measured roughly 28–37x speedups on single edits and halved chunk-gen lighting time versus pre-1.20 vanilla. Light only matters for gameplay parity through spawning (monsters need light 0), crops and ice. Steel runs a parallel Starlight/ScalableLux-inspired engine.

**Redstone and ticks: the hardest parity point for multithreaded designs.** The default vanilla wire evaluator iterates a 7-entry Java `HashSet<BlockPos>`. SteelMC reproduces its bucket order exactly: hash=((z*31+y)*31+x), spread h^(h>>>16), &15. Scheduled ticks drain by trigger time, then priority, then sub-tick order. Some ties depend on fastutil/`PriorityQueue` internals. Steel deliberately uses insertion order there. Quasi-connectivity is officially "works as intended" and creates update-order-dependent BUDs. The Redstone Experiments datapack (orientation-based, left-first order) is still opt-in.

Pumpkin runs scheduled block ticks, fluid ticks and entities in parallel rayon batches and uses a fixed direction order for wire. That trades away redstone determinism. Folia-style regions keep determinism only inside a region.

**Entities and AI** are the largest hand-port. There are two AI systems: GoalSelector for older mobs, and Brain for newer ones (over 100 memory types, 27+ sensors, activities; used by villagers, piglins, wardens, frogs, axolotls and others). On top of that come pathfinding node evaluators with per-block path malus, and spawning: mob cap = cap × chunks / 289, categories 70/10/15/5/5/20/5, and spawn-potential biomes. 26.3 made natural spawns data-driven (`natural_mob_spawns` environment attributes). Pumpkin has about 82k lines in `entity/` and still marks mobs and AI as W.I.P. Steel says only a few entities have meaningful behaviour.

**Items, commands, chat.** Recipes and loot are JSON, but special recipes, loot functions and advancement triggers are code. Since 1.21.2 the client receives only property sets and stonecutter recipes, so recipe logic is entirely server-side. The Brigadier `Commands` packet has 57 parser IDs (0–56, ending with `minecraft:uuid`) and flags including 0x20 "restricted". azalea-brigadier (0.16.0+mc26.1) is a reusable Rust port. Signed chat: SHA256withRSA over a message chain (session UUID, index, last 20 seen). Breaking the chain disconnects the client with `chat_validation_failed`. Servers can avoid signing by sending system or disguised chat and setting `enforcesSecureChat=false`.

**Effort data points.** Pumpkin started Jul 2024, has about 308 contributors, about 265k lines in the main crate, 79k worldgen, 38k protocol and 1.5M generated. It targets 26.3 plus Bedrock and is still pre-1.0. SteelMC started Oct 2025, has about 54 contributors, about 328k lines in steel-core and 27k worldgen, and is pre-alpha with complete worldgen.

## Part B: extensibility
- **Native Rust dylibs.** Pumpkin still ships a `libloading` loader that passes `Box<dyn Plugin>` across the boundary. That needs the same rustc and crate versions (it checks a u32 API version). crABI is still experimental. `abi_stable` 0.11.3 was last released in Oct 2023. `stabby` (72.1.16, Jul 2026) is active but has trait-object performance caveats since Rust 1.78.
- **WASM.** Pumpkin's primary system is wasmtime component model (WIT v0.1, about 50 interfaces), `wasm32-wasip2`, component-model-async / WASIp3, wasm-gc and exceptions (for Kotlin and C#), `StoreLimits` memory caps, signed-plugin marketplace metadata, and a WASI capability permission list. It sets no fuel or epoch CPU limit. WASI 0.3 shipped Jun 11 2026 (first final implementation in wasmtime 46; current is 49.0.1).
- **Measured call cost on wasmtime 49** (scalar args): cdylib about 2 ns; core module about 27 ns; component about 187 ns without async and **about 684 ns with `concurrency_support(true)`**. Epoch interruption costs about 10%; fuel is deterministic but slower.
- **Criticism.** Pumpkin issue #2299 (Jun 2026) argues that guest language runtimes (Python, .NET) mean a runtime inside a runtime with memory use nobody can see or control, and proposes Luau instead.
- **Scripting.** mlua 0.12.1 supports Lua 5.1–5.5, LuaJIT and Luau, with sandbox, memory limit, interrupt and an optional JIT. Rhai is 2–3x slower than Python. deno_core, rquickjs and boa are also available.
- **Framework approach.** Valence (bevy_ecs) is stuck on 1.20.1 with maintenance-only commits. Minestom (Java) shows the "no vanilla by default" library model works well for minigames. SteelMC plans a native Rust API first, with WASM or scripting layered on top later.
- **Bukkit compatibility.** PatchBukkit (Pumpkin, Java 25, JNI/FFM plus protobuf, reimplements the Bukkit API on a dedicated JVM thread) and the Lodestone proposal (back Paper's NMS with JNI) show it is feasible. The hard parts are threading and reentrancy, object identity, JNI marshalling cost, and NMS/reflection plugins.

## Part C: operations and security
- **Velocity modern forwarding:** login plugin channel `velocity:player_info`, HMAC-SHA256, versions 1–4 (4 = LAZY_SESSION).
- **Server list ping and legacy protocols:** status JSON (version, players.sample, description, 64x64 favicon, enforcesSecureChat) and legacy `0xFE` ping.
- **RCON:** TCP 25575, types 3/2/0, 1446 B request, 4096 B response fragments, plaintext.
- **Query:** UDP GameSpy4 challenge token bound to IP/port, rotates every 30 s.
- **Management protocol:** vanilla JSON-RPC over WebSocket since 1.21.9, bearer secret.
- **Protocol limits:** packet ≤ 2,097,151 B; serverbound uncompressed ≤ 8,388,608 B; NBT depth 512 and 2 MiB quota.
- **Paper defaults worth copying:** packet limiter 500 packets per 7 s, then kick; tab-spam 500; recipe-spam 20; book page 2,560 B; 5 joins per tick.
- **Online-mode auth:** RSA-1024, AES/CFB8, `hasJoined` with SHA-1 two's-complement hash.
- **Transfers and cookies (1.20.5+):** the transfer packet and cookies, with `accepts-transfers`. Cookies are client-controlled, so sign them.
- **Profiling:** `/tick query` (1.20.3); Paper bundles spark since 1.21.
- **Implementation risk:** Pumpkin's Java decoder pre-reserves a buffer as large as the packet's *declared* uncompressed length (up to 8 MiB), which could let an attacker inflate memory per connection. Its exploitability is unverified.

Process note: one crates.io API request during this research sent a User-Agent containing the user's email address. All later requests used a generic User-Agent.

## Design implications
- Build a version-pinned data pipeline first: run the vanilla data generator on the unobfuscated server jar, extract datapack JSON, NBT templates and reports, codegen Rust registries and structs, and regenerate every quarterly release. Budget a protocol and data bump every ~3 months (26.1, 26.2 and 26.3 were Mar, Jun and Sep 2026).
- Make parity measurable. Build a differential harness: (a) block-for-block chunk comparison against a patched vanilla reference (per-chunk biome cache reset, fixed feature order, ordered hash collections, as SteelMC does); (b) data-driven GameTest structures run headless on vanilla (net.minecraft.gametest.Main) and on our server. Gate CI on zero mismatches, not a tolerance like Pumpkin's 6,000 per chunk.
- Worldgen execution: transpile density functions to native Rust at build time for the vanilla presets (SteelMC's approach), and keep a runtime interpreter fallback for custom datapack worldgen. Embed vanilla's constructed multi-noise RTree rather than rebuilding it. Put exact Java numeric and RNG primitives (LCG, Xoroshiro128++, MD5 seeding, Mth tables) in one audited module.
- Decide determinism policy explicitly. For 'vanilla mode', gameplay (block updates, scheduled ticks, redstone, entities inside an interaction domain) must run in a deterministic serial order, including Java HashSet<BlockPos> bucket-order emulation for wire and vanilla DRAIN_ORDER for ticks. Parallelize only work that is order-independent or region-isolated: chunk gen, lighting, packet encode/decode, I/O, and pathfinding precompute. Do not copy Pumpkin's parallel scheduled ticks if redstone parity is a goal.
- Offer optional non-vanilla fast paths behind config flags (e.g., Alternate Current wire, Redstone Experiments order, relaxed spawn and AI budgets), so 'vanilla-exact' and 'performance' modes are both explicit and testable.
- Roadmap order (cheapest and most valuable first): (1) protocol, login, config phase, status ping, encryption, compression, proxy forwarding, commands framework, permissions; (2) Anvil load and save of vanilla-pregenerated worlds plus flat and void generators, and lighting; (3) block states, updates and shapes, fluids, scheduled and random ticks, block entities, inventories, recipes, loot; (4) full noise worldgen (noise, surface, carvers, features, structures) with a parity CI gate; (5) entity physics, combat, GoalSelector, Brain, pathfinding, spawning; (6) redstone parity, advancements, raids, villagers, end fight, signed chat. Steps 1–3 already let minigame and lobby servers use the core, Minestom-style.
- Extensibility tiers: (A) first-party compile-time Rust API (in-tree crates, feature-gated, ECS or trait hooks) for performance-critical extensions, as SteelMC plans and Valence does; (B) sandboxed third-party plugins via wasmtime component model with versioned WIT, StoreLimits memory caps, epoch interruption for CPU, capability permissions and signature checks; (C) optionally an embedded Luau (mlua) for lightweight scripting with central resource accounting. Avoid Rust-ABI dylibs (Box<dyn Trait> across dylibs); if native third-party plugins are needed, use a C ABI or stabby.
- Design the plugin ABI around call cost: about 0.19 µs per component call without async and about 0.68 µs with component-model async (wasmtime 49). Expose coarse, batched events (per-tick batches, cancellable high-level events) and query APIs returning bulk data. Never call into WASM per block update or per entity tick. Consider not enabling concurrency_support on hot paths.
- Treat Bukkit/Paper compatibility as an optional out-of-process or separate-thread JVM bridge (PatchBukkit-style), not a core requirement. NMS, reflection and packet-hooking plugins won't work, and threading or reentrancy with a Rust world lock is the main risk.
- Security baseline: enforce 2,097,151-byte frames and 8 MiB decompressed limits with streaming inflate that never pre-allocates from attacker-declared lengths; enforce NBT depth 512 and a 2 MiB quota; string and collection length caps per field; per-connection token-bucket packet limiter (Paper default 500 packets per 7 s) plus per-packet-type limits (tab-complete, recipe, book edits); login and handshake timeouts; max joins per tick; async hasJoined with timeout; HMAC-verified Velocity forwarding; RCON off by default and bound to localhost; a network fuzzer in CI.
- Ops surface to plan: TOML config with server.properties-equivalent keys, status ping with favicon, legacy 0xFE ping, RCON, Query, the vanilla JSON-RPC management protocol (1.21.9+), transfer and cookie support (signed cookies), ops.json and op levels 0–4 plus a node-based permission system, /tick query-style metrics and a built-in sampling profiler export.

## Open questions
- Are the new 26.3 density functions (log, pow, sqrt, lerp) computed with Java Math or StrictMath? Math intrinsics may differ by up to 1 ulp across JVMs and CPUs, which would make bit-exact worldgen impossible even between vanilla instances. Unverified.
- Why does Pumpkin tolerate up to 6,000 block mismatches per chunk: vanilla nondeterminism, version drift, or known unported pieces? No rationale was found in the shallow clone.
- How many vanilla redstone contraptions actually depend on the Java-collection tie-break orders that SteelMC deliberately does not reproduce (the LevelChunkTicks ties)? Not measured.
- What is the real per-event cost of the component model when events pass strings, lists or resources (entity handles)? The 187–684 ns figures are scalar-only microbenchmarks with unstated hardware.
- Luau call overhead via mlua versus wasmtime components was not measured here; both would need benchmarking on the target hardware.
- How complete PatchBukkit is (which Bukkit APIs and events work, which popular plugins run) could not be determined from its README or ARCHITECTURE.md.
- SteelMC's tracker page did not expose per-category implementation counts, so its non-worldgen completeness is only qualitatively known.
- Does vanilla reject compressed frames whose declared uncompressed size is below the threshold (the 'badly compressed packet' check)? This affects strictness of our decoder but was not re-verified for 26.3.
- Whether Paper's current redstone-implementation option (VANILLA / EIGENCRAFT / ALTERNATE_CURRENT) still exists in 26.x was not re-verified.

## Omissions
- 26.3 moved all density-function and noise evaluation to single-precision f32, including every intermediate step. This decides the worldgen core. Bit-exact parity now means matching Java float semantics (strict IEEE since JEP 306) in f32. f32 also doubles SIMD lane width, which makes transpiler or SIMD designs more attractive. Both existing Rust parity references need rework for 26.3: Steel's transpiler emits f64 and targets 26.2, and Pumpkin's samplers already return f32. Build the port on 26.3 semantics from day one.
- 26.3 also restructured noise settings and features, so pipelines built against 26.2 JSON break. surface_rule became material_rule. The aquifers and ore_veins objects replace router fields. The beardifier is no longer implicit. size_horizontal and size_vertical moved into interpolated. worldgen/configured_feature became worldgen/feature with inline config. About 8 feature types were removed and 3 renamed. Budget roughly a full worldgen-schema migration per drop, not a small tweak.
- 26.4 Snapshot 1 (2026-09-22) changes the handshake and ops surface. The intention host field is now up to 1024 chars with URI-query properties; keys starting with '_' are reserved, and '<id>@<host>' maps to _id. It adds the allowed-connection-ids, enable-legacy-status and status-contact-details (status JSON 'contact') settings, a properties map on the transfer packet, and a minecraft:mod_list configuration payload. Handshake parsers must stop assuming a 255-char host. Legacy BungeeCord forwarding, which packs NUL-separated data into the host field, will collide with this. The properties are unencrypted, so never use them for auth.
- Pumpkin PR #2828 (open, Aug 2026) uses one WIT API to generate either WASM components or native C-ABI cdylibs. This middle path between the 0.19–0.68 µs component-model calls and fragile Rust-ABI dylibs should be weighed when choosing the extensibility tiers.
- Legal and licensing risk. The Mojang EULA is unchanged by de-obfuscation, and decompiled source is not licensed for redistribution. Porting it line by line and publishing the result carries copyright risk. Reusing code also forces a license: Pumpkin is GPL-3.0 with plugin API crates under MIT/Apache-2.0, and SteelMC is AGPL-3.0-or-later, so copying Steel code makes the server AGPL (network-use clause). Choose the project license and a clean-room policy before borrowing code.
- The Steel speedups are measured against Fabric with no performance mods. There is no C2ME, Paper or Folia baseline, so 18.8x overstates the gap to an optimized Java server. Run your own benchmark against C2ME before using it for capacity planning.
- Server-side lighting is still worth optimizing. Spottedleaf says vanilla 1.20+ is still about 2x slower than Starlight on propagation tests, and Paper and Folia keep Starlight through Moonrise. 'Vanilla absorbed Starlight' does not mean a Starlight-style engine gains nothing on a server.
- Answers one open question: Paper's world config still documents misc.redstone-implementation with VANILLA (default), EIGENCRAFT and ALTERNATE_CURRENT, so a switchable redstone mode has current precedent.
- The Management Protocol has TLS on by default (since 25w37a). Its API version went to 3.0.0 in 26.2 and 3.1.0 in 26.3, where it also starts before the game server and adds world-upgrade notifications. Plan for TLS and a versioned JSON-RPC surface, not a plain WebSocket.
- Rust ecosystem crates lag Mojang's quarterly drops. azalea-brigadier's newest crates.io release is still 0.16.0+mc26.1 (2026-03-28), two releases behind. Depending on third-party protocol or data crates adds version lag every quarter.
- Correction to the effort data: Steel's worldgen is not about 27k lines. steel-core/src/worldgen holds another ~39k lines beyond steel-worldgen, so the total is about 66k. Pumpkin's generation/ is about 59k lines and entity/ about 82k, matching the report.
- Pumpkin's decoder rejects uncompressed frames above the threshold but has no 'badly compressed' check for compressed frames whose declared size is below the threshold. It also reserves up to 8 MiB from the declared length before inflating. Make both checks explicit in the security baseline (not live-verified against vanilla 26.3's CompressionDecoder).
