## User requirements (decided by the user)
- Minecraft **Java Edition only**.
- **Vanilla-compatible**, but squeeze performance by any means; the user explicitly **accepts approximations that reduce computation** (Paper/Folia-style trade-offs are OK). Design must make every deviation explicit and ideally configurable.
- **Latest official release only** — verified: **26.3** (protocol **777**, data/world version 5023, released 2026-09-15, requires Java 25 for the vanilla jar). Multi-version is left to ViaVersion/ViaProxy in front.
- **WASM plugins** as the extension mechanism.
- Dev machine: Windows 11, Ryzen 7 5700X3D (Zen 3, 8C/16T, has AES-NI and VAES-256), Rust stable 1.97 locally (current stable 1.98.1), JDK 25 installed. Deployment likely Linux. Greenfield, very small team (user + AI assistant). Project license not chosen yet.

## Version & protocol facts
- Year-based versions since Dec 2025: 1.21.11 (774, last obfuscated) → 26.1 (775, 2026-03-24, first unobfuscated) → 26.2 (776, 2026-06-16) → 26.3 (777, 2026-09-15). 26.4-snapshot-1 out (2026-09-22). Expect ~4 protocol breaks/year, each with 10+ snapshots warning.
- Each drop reshuffles IDs massively: 26.2→26.3 moved 104 clientbound Play IDs, 17 serverbound, 10 of 20 clientbound Configuration IDs; ~98% of block IDs and ~95% of item IDs shifted; block states 32,366 → 35,723. Synchronized registries grew 29 → 32 (new: decorated_pot_pattern, block_transformer, worldgen/block_state_provider). ⇒ Nothing may be hardcoded; all IDs/registries/tags codegen'd from the pinned jar.
- Vanilla data generator (`java -DbundlerMainClass=net.minecraft.data.Main -jar server.jar --reports --server`, ~15 s, 10,038 files): packets.json (IDs only, **no field layouts**), blocks.json (1286 blocks/35,723 states), registries, item components, datapack JSON (worldgen, recipes, loot, tags: 883 tag files), commands, JSON-RPC management OpenRPC schema (3.1.0). Collision shapes/entity metadata need an extractor mod (Pumpkin Extractor = MIT, SteelExtractor = CC0) or javap/decompiled analysis. PrismarineJS minecraft-data only covers up to 26.1 — don't depend on it.
- Unobfuscated bytecode since 26.1 (no mappings published): decompiled names readable. **EULA unchanged — decompiled source is not licensed for redistribution; line-by-line porting and publishing carries copyright risk. Need a clean-room / behavior-reference policy.**
- Connection: Handshake → Status | Login → Configuration ⇄ Play (Configuration re-enterable from Play). Packet counts 26.3: Handshake 1, Status 2/2, Login 6/5, Config 21/10, Play 144/69. Login Success has Session ID UUID (since 26.2). Cookies ≤5 KiB, Transfer (intent 3).
- Framing: VarInt length (max 3 bytes, frame ≤ 2,097,151), zlib compression (threshold default 256; compressed ≤2 MiB, uncompressed ≤8 MiB), AES-128-CFB8 continuous stream (online mode only; offline never encrypts), RSA-1024, Minecraft signed-hex SHA-1. Keep-alive 15 s; vanilla ReadTimeout 30 s. Custom payload 32767 B serverbound / 1 MiB clientbound. Text components are NBT on the wire.
- Auth: authlib 10.0.77 resolves endpoints from discovery.minecraftservices.com (no hardcoded fallback in vanilla). Secure chat (chat_session_update, signed message chain) is a separate big decision.
- Registry sync: Known Packs `minecraft:core` = version id lets the server send entries without NBT only if the client's reply equals the offered list exactly; else full NBT. Tags always sent in full. Cache encoded registry/tag packets once.
- Chunk wire format: per section `short blockCount, short fluidCount`, block paletted container (0 single, 1–4 → 4-bit linear, 5–8 hashmap, else direct; vanilla emits direct 16 bits for 35,723 states; client accepts any direct bpe ≥9 that fits), biome container 4×4×4 (26.4 snapshot moves to 16³ per-block biomes — make dimensions per-version). Entries never cross u64 boundaries; array length implicit. Chunk packet ≤2 MB; bundles ≤4096; client chunk-batch ack (max 10 unacked batches).
- Disk: Anvil (4 KiB sectors, compression 1 gzip / 2 deflate default / 3 none / 4 LZ4 / 127 custom, +128 external .mcc). 26.1 layout: dimensions/minecraft/*/{region,entities,poi}, players/*. Don't implement DataFixerUpper; require vanilla --forceUpgrade for old worlds.
- 26.4 snapshot: handshake host up to 1024 chars with URI-query properties (`_` keys reserved) — collides with BungeeCord legacy forwarding in the host field.
- Proxy: Velocity modern forwarding (HMAC-SHA256, v1–v4 LAZY_SESSION); BungeeCord legacy/BungeeGuard (host up to 32767). **Velocity decompresses and recompresses backend traffic** ⇒ behind a proxy the backend should use compression threshold -1 and offline mode + forwarding: no compression and no encryption on the backend hot path. Proxy mode must be first-class.
- Test clients: **no bot tool speaks 26.3 natively yet** (azalea main = 26.2 with a 26.3 branch, needs nightly; BotMark 26.2; rust-mc-bot 1.21.8 GPL; Mineflayer 26.1). ViaVersion 5.12.0 supports 26.3 ⇒ ViaProxy hop, or write our own minimal bot (we own the codec anyway). Real 26.3 client works for manual testing.
- No stable Java reference server for 26.3 yet (Paper 26.3 = ALPHA, Folia 26.2 = BETA). Vanilla 26.3 jar is the reference.

## Rust landscape lessons (weighted: much of FerrumC v2 / Hyperion recent work is AI-driven or unmerged)
- **Pumpkin** (GPL-3.0, very active, 26.3, broadest features, OOP `Arc<dyn Entity>` + atomics, rayon par_iter over worlds/players/entities/block ticks → nondeterministic order). In Aug 2026 it did an **async→sync refactor (~900 files, +50k/−56k)**: game logic sync in the tick, Tokio only for I/O, rayon for CPU; bugs came from Tokio/worker-pool crossover and `Arc<Chunk>` leaks blocking unload. Worldgen parity on master is unknown (a batch of ~20 AI parity PRs was rejected); its tests tolerate 6,000 mismatched blocks/chunk and only cover noise/surface. Pistons still broken. Plugins: wasmtime component model + WIT (~46 WIT files, 8 SDK languages), plus native libloading loader; PR #2828 generates a C-ABI cdylib from the same WIT. No MSPT under load published; ~100 MB idle measured on old 1.21.1.
- **SteelMC** (AGPL-3.0, 26.2, nightly): one OS thread per world tick, packets processed between ticks, plain structs + parking_lot; worldgen **block-for-block parity on 7,500 chunks for 26.2** via build-time density-function → Rust transpiler (CSE, bounds-based branch elision, SIMD) and a stage-pyramid scheduler; removed vanilla's own nondeterminism in reference dumps. 18.8× chunk-gen vs **stock Fabric without perf mods** (not vs C2ME/Paper); memory advantage flips at 301×301. Its transpiler emits f64 ⇒ **not valid for 26.3**, which moved density functions/noise to **f32 in all intermediate steps** and restructured noise settings (material_rule, aquifers/ore_veins objects, no implicit beardifier, configured_feature→feature, ~15 new density functions, removed cache_2d/flat_cache/…; new TERRAIN status merging NOISE/SURFACE/CARVERS). No Anvil support.
- **FerrumC v2** (MIT, 1.21.8, AI-agent-built rewrite, unshipped): actor shards of 8×8 chunks, SlotMap + component Vecs, message passing, rejected bevy ("workload is spatial"). **Hyperion** (Apache-2.0): evenio→flecs→bevy→flecs churn; flecs-rust immature (forked, multithread asserts); 5,000 bots @1.42 ms/tick benchmark is from 2024 on old stack and excludes proxy fan-out; offloads broadcast to horizontally scaled proxies. **Valence** (MIT, bevy_ecs, 1.20.1) maintenance-only; per-chunk message buffers so packets encoded once. **MCHPRS**: redstone graph compiler (subset of components only).
- Two of three active full servers are **non-ECS**. bevy_ecs 0.20-rc is out (breaking every ~3–4 months). Don't bet the core on a third-party ECS; if ECS-like layout wanted, use owned SoA / slotmap per region with explicit system order.
- Reusable (permissive): RustCrypto aes/cfb8/rsa/sha1, libdeflater or zlib-rs (via flate2), lz4_flex, zstd, simdnbt (MIT but nightly-only; stable fork exists), glam, redb/heed/fjall, slotmap, mimalloc, tracing(+tracy), wasmtime. Study-only (copyleft): Pumpkin (GPL), SteelMC (AGPL). Must write ourselves: scheduler/threading, world/chunk storage, worldgen (26.3 f32), lighting, entity AI, redstone, inventory/menu semantics, ItemStack data components (~111 types) + entity metadata (big hand-written chunk), Anvil read/write (only full impl is GPL).

## Java ecosystem performance lessons
- **Folia** regionizer: 16×16-chunk sections, merge radius 1 ⇒ regions stay separate only with ≥48-chunk gaps; each region ticked single-threaded by a scheduler (EDF default; work-stealing variant exists); cross-region ops via per-region task queues; global region for time/weather/gamerules/console. Breaks: plugins assuming one main thread, scoreboard API, global selectors, cross-region redstone/entity interactions. **Its 1000-player showcase (7950X3D, ~630 at steady 20 TPS) deliberately spread players across a pregenerated 100k² world** — no evidence regions help clustered organic survival. Crowds end up in one region ⇒ need **intra-region phase parallelism against immutable snapshots** (tracker visibility, pathfinding/POI candidates, packet encoding, lighting of disjoint sections) with deterministic apply in vanilla order. Leaf's bolt-on async attempts (async chunk sender, async target finding) failed: parallelism must be designed into data structures (versioned/CoW sections, SWMR buffers).
- **Minestom**: per-chunk dispatch with one GLOBAL_LOCK held for whole cross-partition access, 1 dispatcher thread by default — reject that model.
- **Moonrise (Paper chunk system)**: ticket-level propagation off tick thread in 64×64-chunk sections under area locks; explicit generation-status DAG with per-status neighbour read/write radii (26.3: EMPTY, STRUCTURE_STARTS, STRUCTURE_REFERENCES, BIOMES, TERRAIN, FEATURES(write r1), INITIALIZE_LIGHT, LIGHT(r2), SPAWN, FULL); parallel-safe statuses on a worker pool; area-dependent queue for FEATURES/LIGHT; separate chunk/entity/POI loads; two-phase unload; full-status transitions (inaccessible/border/block-ticking/entity-ticking) applied on the owning thread. **Never load chunks synchronously on a tick thread.**
- Worldgen throughput: vanilla ~42 chunks/s, Paper ~142, C2ME ~458 at 16 threads on 48-core Xeon with heavy datapacks (workload-specific); C2ME's density-function compiler. Vanilla worldgen already nondeterministic across runs at chunk borders (MC-55596) ⇒ exact feature placement across borders not strictly required.
- Lighting: Starlight algorithm (BFS with separate increase/decrease queues, per-state opacity/conditional shapes, heightmap sky init) still ~2× faster than vanilla 1.20+ propagation; ScalableLux adds parallel light updates. Store nibbles in the chunk; batch light per region at end of tick; SWMR buffers for sending/saving. Light-suppression behavior is a parity gap to document.
- Entities: generational IDs; per-16³-section spatial buckets with per-type sub-indices; per-chunk nearby-player lists at fixed radii; incremental tracker; per-section change timestamps so hoppers/sensors can skip scans. Lithium-style block-entity sleeping (hoppers, furnaces, brewing) with inventory modification counters — can match vanilla timing (incl. 7gt/8gt hopper case); Paper's cooldown-when-full breaks dual-speed sorters.
- Parity policy precedent: Paper keeps `redstone-implementation: VANILLA|EIGENCRAFT|ALTERNATE_CURRENT`. Paper defaults deviate (activation range incl. raiders 64, hopper cooldown). Vanilla already has per-player mob caps (don't list as a deviation). Leaves defaults to vanilla behaviors.
- Bandwidth: entity packets dominate **message count** (86–97%) but only **1–17% of bytes**; bytes are mostly chunk data ⇒ chunk path (caching, compression level, send-rate policy) is the byte lever; entity aggregation is a CPU/packet-count lever.
- Thread budgets: Folia ~cores/8 default tick threads (conservative; showcase overrode), Moonrise ~cores/4 gen workers; keep total threads ≤ cores. Chunk send rate limits (Paper 75/100 chunks/s per player), spiral order, client batch feedback.
- Save pipeline: dedicated IO + compression executors, coalesce writes, serve reads from pending writes, incremental autosave with per-tick budget, configurable fsync.

## Rust implementation facts
- Networking: tokio multi-thread (IOCP on Windows, epoll on Linux); per-connection reader + writer tasks; tick never awaits, pushes per-player batched BytesMut once per tick; **egress bounded by bytes** (soft limit: drop low-priority e.g. chunks; hard limit: disconnect), separate high-priority lane (keepalive/teleport). io_uring: blocked by default Docker/containerd seccomp; tokio support file-only; compio (IOCP+io_uring) as later experiment behind a transport trait.
- Compression: libdeflater fastest at L4/L6 (164/121 MB/s vs zlib-rs 140/99), zlib-rs slightly faster at L1 but worse ratio; inflate libdeflate ~1.9× zlib-rs. **flate2 pitfall**: compress_vec/decompress_vec zero-fill the whole spare capacity each call (Pumpkin hits it) — compress into exact-size slices. Never use miniz_oxide default. Cache compressed chunk packets (invalidate on change).
- Encryption: aes+cfb8 0.9 (ParBlocksSize=1, ~50 MB/s/core est.). Without chunk-packet caching compression dominates join cost (~120 ms vs ~60 ms at VD10); with caching encryption dominates. Batched decryption (~6×) and multi-buffer encryption across connections (VAES on Zen 3+) possible later behind an internal interface.
- Packets: derive macros (Encode/Decode + id/state/direction attribute); IDs/registries/components codegen'd and committed (no heavy build.rs); decoded packets own payloads (bytes::Bytes). Golden-byte tests against captured vanilla traffic (round-trip tests hide symmetric bugs). ItemStack components + entity metadata ≈ 15–20k lines hand work.
- Memory: mimalloc global allocator on all targets (2.7–4.3× vs Windows heap measured); tikv-jemallocator doesn't support MSVC. Per-tick bump arenas. Sections: Single / Indirect(u8 index + palette) / Direct(u16) in memory with bit-packing only at serialization (Pumpkin) **or** vanilla bit-packed in memory (memcpy send) — unmeasured trade-off; dirty flag invalidates cached packets.
- SIMD: std::simd is still nightly; use std::arch with runtime detection (safe since 1.87) or `wide`/`pulp`. 26.3's f32 worldgen doubles SIMD lanes. Avoid pdep/pext on Zen1/2.
- Storage: pluggable ChunkStorage trait; Anvil (zlib + LZ4) on a small blocking pool with positional IO + LRU of region handles; optional zstd whole-region format (Linear-like, 36–48% smaller).
- Observability: tracing spans per tick phase, tracing-tracy feature, `profiling` cargo profile for samply (Windows ETW/Linux perf), tokio-console behind feature, metrics+Prometheus (TPS, MSPT, bytes out, queue depths, compress/encrypt time).
- Testing: codec property tests + cargo-fuzz (nightly) per decoder; deterministic tick tests (seeded RNG, fixed order); differential tests vs vanilla (chunk dumps, GameTest structures headless via net.minecraft.gametest.Main); load tests with own bot or azalea (nightly, separate workspace).

## Vanilla parity cost (effort, data-driven vs hand-port)
- Data-driven (codegen/interpret from jar): registries, tags, recipes, loot tables, advancements, block states/properties, item default components, worldgen JSON (but its *evaluation semantics* must be hand-implemented), dimension types, biomes, damage types, commands tree shape.
- Hand-port logic (large): worldgen evaluation (26.3 f32 semantics; Steel ~66k lines, Pumpkin generation ~59k), structures/jigsaw, features; lighting; block behaviors (~1286 blocks: updates, shapes, fluids, random/scheduled ticks); block entities; redstone (update order DFS W,E,D,U,N,S, 1,000,000 chain limit, quasi-connectivity, Java HashSet<BlockPos> iteration order matters for wire); entities (physics, combat, GoalSelector + Brain AI, pathfinding; Pumpkin entity/ ≈ 82k lines); mob spawning (cap × chunks/289, categories 70/10/15/5/5/20/5; 26.3 moved spawns to layered environment attributes); inventories/menus; commands (Brigadier); advancements; raids/villagers/end fight; signed chat.
- Exact Java numeric/RNG primitives in one audited module (LCG, Xoroshiro128++, MD5 seeding, Mth tables, Java float semantics; open question whether new 26.3 density ops use Math vs StrictMath).
- Suggested roadmap order: (1) protocol/login/config/status/crypto/compression/proxy forwarding/commands/permissions; (2) Anvil load/save of vanilla-pregenerated worlds + flat/void gen + lighting; (3) block states/updates/shapes, fluids, ticks, block entities, inventories, recipes, loot; (4) full noise worldgen with parity CI gate; (5) entities physics/combat/AI/pathfinding/spawning; (6) redstone parity, advancements, raids, villagers, end fight, signed chat. Steps 1–3 already usable for lobby/minigame.

## WASM plugin facts
- wasmtime 49.0.1 (2026-09-24); WASI 0.3 final shipped 2026-06-11 (wasmtime ≥46). Host→guest call cost (single-author microbench, scalar i32, order-of-magnitude): component model ~187 ns sync, ~684 ns with concurrency_support/async; core module ~27 ns; native cdylib ~2 ns. ⇒ **Coarse, batched events; never call WASM per block update or per entity tick.** Use StoreLimits (memory), epoch interruption (CPU), capability permissions, versioned WIT. Pumpkin has no fuel/epoch limits and hit re-entrancy bugs (#2056, #3593). Pumpkin PR #2828: same WIT → WASM component or native C-ABI cdylib. Rust-ABI dylibs: no stable ABI (avoid). Folia lesson: plugin threading contract must be region-aware from v1 (region-scoped schedulers, async-only cross-region APIs).

## Security baseline
- Frame ≤2,097,151 B; decompressed ≤8 MiB with streaming inflate never preallocating from attacker-declared sizes; reject compressed frames declaring size below threshold; NBT depth 512 + 2 MiB quota; per-field string/collection caps; token-bucket packet limiter (Paper 500 pkts/7 s) + per-type limits (tab-complete, recipe book, book edit); login/handshake timeouts; max joins per tick; async hasJoined with timeout; HMAC-verified Velocity forwarding (constant-time); RCON off by default/localhost; fuzzer in CI.

## Ops surface
- TOML config with server.properties-equivalent keys; status ping + favicon + legacy 0xFE ping; RCON; Query; vanilla JSON-RPC management protocol (3.1.0, TLS default on); transfer/cookies; ops.json levels 0–4 + node permissions; /tick-style metrics; built-in sampling profiler export.
